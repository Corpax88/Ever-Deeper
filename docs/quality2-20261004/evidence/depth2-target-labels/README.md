# Depth 2 target labels and shared Depth 1 presentation

Depth 2 now uses the same unshaded, outlined 24px logical-viewport target text as Depth 1. The shared helper owns only presentation. Both worlds retain their existing target selection, damage, words, resource colors, brackets/rings and approved art. Text stays constant through camera zoom, avoids the native hero and hides when its target clears. Main reserves `TargetLabel` for all notice owners in both mine phases.

The accepted production source is `deaa7088d75d473b0c16951bc05f19c4db7800c4`, CI run `37227129258`. `package-contract.json` identifies the exact production PCK used for final parity/resumption and proves that the earlier D2 matrix used byte-identical target owners, helper, camera and notice-anchor function. No production files changed during the final probe corrections.

## Evidence and limits

- `d2-matrix/report.json` preserves the original **99/101** report at 667×375 and 844×390 CSS-equivalent sizes. All target selection, text, 24px zoom invariance, lighting, native-hero clearance, viewport containment and simultaneous skill/pickup/achievement placement checks passed. The two failed checks assumed that clearing a target alone must free an achievement slot. The remaining native hero, fixed HUD and future steering area can still occupy it; those expectations were corrected in the narrow checks below.
- Ore coverage uses authored Rootiron node 84 at cell (31,69). The fixture revealed it with 9 ordinary terrain strikes along 16 grid cells. It did not inject ore or change the node's HP 480/shell 95. Deepstone, Ancient Bedrock, Starforge-required terrain and 1.6× zoom are also rendered. Natural target selection is used for every D2 case.
- `resume-844/report.json`: **6/6**. The retained First Chip notice pauses while blocked, then becomes visible and reaches hold after the miner follows open passage cells. This is an explicitly identified slice of `resume-before-context-fix/report.json`; that original also preserves a separate failed 667px fixture attempt.
- `resume-667/report.json`: **10/10** on the final production package. The notice stays paused while no slot fits. The fixture follows the mined passage to the actual `depthExit` shaft cell and invokes the world's normal ascent action, then places the miner on the legal D1 entrance floor. First Chip resumes visibly in hold with the native hero, HUD and a naturally selected Stone label present. This proves retention through normal ascent and legal return-position states; it does not claim that the fixture walked the entire D1 route. The earlier fixture used `entry_spawn`, which lies outside the shaft's interaction radius; that failed attempt is preserved, not treated as a production defect.
- `d1-parity/report.json`: **62/62** on the final package. All 10 cases retain identical words, target cells, font size and zoom compared with the pre-extraction reference. `comparison.json` is behavioral parity, not pixel identity: the separately approved DOWN camera framing moves the copper/hero position, while other position differences are below 0.15 logical pixels of easing. Actual 667px ore, 667px zoomed ore and 844px tool-lock images were inspected.

The manifest lists all original images by name, absolute scratch path and SHA256. No PNG copies are stored in this documentation directory. Diagnostic failed resumption images remain in their original directories. The final 667px image uses the normal terrain process so the returned mine is fully rendered. `acceptance.json` states exactly which checks close the presentation scope; broader browser, ordinary-play and journey acceptance belongs to the release reports.

## Reproduction

Use `tools/review_depth2_target_labels.gd` with a graphical Godot 4.7.2 renderer, isolated `MODS_OUT` directory and the production PCK identified in `package-contract.json`. Set `DEPTH2_RESUME_ONLY=1` to run only the deferred-notice checks, and optionally `DEPTH2_WIDTH=667` for the small return case. Use `tools/review_target_labels.gd` for the D1 parity matrix. The script file must be passed by absolute filesystem path when using the production PCK, which intentionally excludes review tools.
